## Implemented
- Added unified CoreTrafficStats cumulative download/upload counters.
- Native WireGuard UAPI rx_bytes maps to download and tx_bytes to upload. NativeCore socks-tun uses the opposite internal accounting direction and is normalized explicitly. Tunnel-only keepalive counters are not shown as user traffic.
- AetherCore exposes embedded TUN-to-SOCKS bridge counters only when that bridge exists. System-proxy mode intentionally reports no device-wide speed because it does not capture all device traffic.
- Added a session-owned 1-second sampler, interrupted on session replacement and teardown; it rechecks session ownership after each counter read so an old session cannot overwrite a new session's UI state.
- Added a compact home-card row for live download/upload speed. Unsupported modes say so; first sample says “采样中”. No synthetic probe traffic is counted.
- Added a pure rate calculator and unit tests; CI runs testDebugUnitTest before APK assembly.

## Risks and validation
- Rate is the core data-plane byte rate, not a speed-test result or promise of application payload throughput; it includes protocol/IP overhead according to each core's counters.
- Aether bridge counters and Native WireGuard UAPI counters are operational indicators but are not guaranteed byte-for-byte comparable between cores.
- System-proxy mode remains unsupported until LocalProxy exposes reliable per-session counters.
- CI build and APK metadata/integrity must be verified after commit. No Android physical-device test is available in this run.
